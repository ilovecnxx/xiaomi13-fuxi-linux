## 4. 仍存在的问题

### 14:03 后续复验（modem8 / #214，已装 pd-mapper）
- 在 s2idle2 rootfs 安装 Ubuntu 26.10 官方 arm64 包 `protection-domain-mapper` 1.0-4ubuntu6；APT 模拟为仅新增该包，依赖已满足；服务 enable/active。
- 按既定流程刷入 modem8/#214 并重启。PDR 日志出现 `service lookup for tms/servreg failed: -6`；基带启动后仍在 `ipa_ipfltri_sys_mem_init` 对 45056 字节 SMEM 的断言处崩溃，自动恢复后 14:06:53 再次同样崩溃并最终 offline。QMI 服务曾短暂出现，但不构成稳定通过；ModemManager 仍报缺 net port。
- 结论：单独安装并启用 pd-mapper 未解决故障，也不能证明它是唯一根因。测试后已刷回 s2idle2/#207，回读校验通过，健康检查失败 0；日志 `work/claude-logs/rtest-20261030-140250/summary.txt`、`work/claude-logs/rtest-20261030-140651/summary.txt` 及 #214 上一启动 journal。
- 源码语义复核：本地 errno 表中 `ENXIO=6`；PDR 代码只在 QMI domain-list 事务成功、但响应列表无匹配 `service_path` 时返回 `-ENXIO`。无应答走事务超时 `-ETIMEDOUT`（`-110`）。故记录的 `-6` 不是“servreg 无应答”的直接证据。该原始 PDR 行目前未出现在已保存日志里，下一轮应保存完整 #214 journal 或加域列表字段诊断。

### 基带（计划第 2 项，用户优先）
- 现象：基带能起来、QMI 服务全注册，但每次都崩。#209 是 13.7 s 的 `ipa_ipfltri_sys_mem_init` SMEM 断言（之后 INIT_MODEM_DRIVER 两次 -110）；
  #210 是 53 s 的看门狗 `DOG detects stalled initialization`。同一配置两次的崩溃点不同。
- 已排除：SMEM 空间不足（剩约 436 KiB，item 497 已由主线 IPA 分配 0xb000）；固件缺段（b14/b21/b30 是 filesz=0 的空段）。

  **同一次开机内不能重试，每次试验都要重启手机**。
- ModemManager 报 `Failed to find a net port`：没有 rmnet/IPA 网络接口。

## 5. 新增的无效方案（不要重复）
- 用 `amixer -c0 cset name=…` 设 wcd938x 控件：报 `Cannot find the given element`，要用 `amixer -D hw:0`。
- 照搬厂商 mixer_paths 的 SWR 通道号（SWR_MIC9）：主线 port 映射不同，第二麦是 SWR_MIC1。
- 在 Linux 侧预分配 SMEM item 497 修基带断言：主线 IPA 已经分配过了，无效。
- 基带崩溃后 `echo start` 或 `systemctl restart rmtfs` 重试：remoteproc 卡住，无效，只能重启手机。

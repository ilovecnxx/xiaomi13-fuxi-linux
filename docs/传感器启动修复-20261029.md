# 2026-10-29：传感器数据、桌面接入与 ADSP/Phosh 启动修复

在 `daily-pm1` / 内核 `7.3.0+ #168` 上继续；本轮不改内核镜像和 Android 分区。

## 已确认的问题

- `hexagonrpcd` 的文件服务是虚拟文件树：`socinfo/` 必须放到 `-R` 根目录下，
  不是自动读取 Linux `/sys/devices/soc0`。原脚本没有复制，六项设备信息均缺失。
- 小米传感器的 56 个主体配置在 `/odm/etc/sensors/config`；旧脚本只复制了 vendor 下的一个 CHRE 配置。
- 上游 hexagonrpc v0.4.0 没有 ODM 路径和 `sns_reg_version` 文件映射。
- `adb pull` 未使用 `-a`，随后 `tar -xmf` 又明确忽略文件修改时间。
  Android 原配置 mtime 是 `1230768000`，与已生成注册表中的 56 个缓存条目一致；
  复制后变成当前时间，触发重新解析与写临时文件。已在 Android 只读 `stat` 核实。
- `adb pull -a` 同时保留了 Android 文件的 0600 权限。Linux 服务以 `fastrpc` 身份运行，
  所以部署后需单独调整副本为 root:fastrpc、目录 0750、文件 0640，仍保留 mtime。
- `ssccli` 0.4.4 即使打印 `SSC QMI Service not found` 也可能退出 0。
  旧脚本因此错误地把传感器步骤记为完成；新脚本同时检查输出。
- 已重编的 SensorProxy 支持全部四个 SSC 驱动，但发行版 udev 规则只标记 light/compass，
  漏掉 `ssc-accel`、`ssc-proximity`。设备规则补齐后，两者均被桌面识别。
- udev 在 SSC QRTR 400 发布前启动 SensorProxy，导致它报告无传感器后退出。
  新 drop-in 排在 hexagonrpcd 后，并等待实际服务发布，不以 daemon 进程存在代替就绪。

## 可用的只读配置视图

只补齐文件、mtime 和权限仍不足以取得 SSC 数据。干净启动时使用
`/var/lib/fuxi-sensors-prebuilt`，引用 Android 已生成的 311 个注册表文件、版本和设备信息，
同时将 vendor/ODM 配置目录保持为空，才稳定发布 QRTR 400。
原始 56 个 ODM 配置和 1 个 vendor 配置仍保留在 `/var/lib/droid-juicer/sensors`。
这样避免要求只读文件服务重新生成注册表；并没有开放真实 persist 写权限。

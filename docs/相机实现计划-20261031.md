## 2. 第一步：OV13B10（cam2）的具体改动

### 2.1 内核配置

```bash
cd build/linux
./scripts/config \
  --enable MEDIA_SUPPORT --enable MEDIA_CAMERA_SUPPORT --enable MEDIA_CONTROLLER \
  --enable VIDEO_DEV --enable VIDEO_V4L2_SUBDEV_API \
  --enable VIDEO_QCOM_CAMSS --enable VIDEO_OV13B10
make ARCH=arm64 olddefconfig      # 让 Kconfig 补齐依赖（I2C、V4L2 fwnode、PM 等）
grep -E 'CAMSS|OV13B10|MEDIA_SUPPORT' .config   # 确认都为 y
```

注意：`camss.c` 的 sm8550 资源需要 `CONFIG_INTERCONNECT`（icc）与 `CONFIG_VIDEO_V4L2_SUBDEV_API`，
olddefconfig 后要复核一遍，避免只开了 CAMSS 但 icc 没开导致 probe 失败。

### 2.2 DTS 传感器节点（加进 `sm8550-xiaomi-fuxi-camera.dtsi` 的 `&cci0_i2c0`）

cam2 的电源/时钟/复位已经在 `cam2_power` 节点里（`vio=vreg_l2c_1p8`、`vana=GPIO91 2.8V`、
`vdig=vreg_l1c_1p2`、`clocks=CAM_CC_MCLK1_CLK`、`reset-gpios=tlmm 117`）。
传感器节点要按 `ov13b10` 的 binding 引用它们：

```dts
&cci0_i2c0 {
	status = "okay";

	camera@10 {
		compatible = "ovti,ov13b10";
		reg = <0x10>;                 /* 待确认：先用 i2cdetect 在 Android/Linux 上验 */
		clocks = <&camcc CAM_CC_MCLK1_CLK>;
		clock-names = "xvclk";
		reset-gpios = <&tlmm 117 GPIO_ACTIVE_LOW>;
		power-domains = <&camcc CAM_CC_CAMSS_TOP_GDSC>;

		avdd-supply = <&cam_ultra_avdd>;   /* 2.8V，GPIO91 开关 */
		dvdd-supply = <&vreg_l1c_1p2>;     /* 1.2V */
		dovdd-supply = <&vreg_l2c_1p8>;    /* 1.8V */

		port {
			ov13b10_ep: endpoint {
				data-lanes = <1 2 3 4>;        /* 待确认 */
				link-frequencies = /bits/ 64 <400000000>;
				remote-endpoint = <&csiphy0_ep>;
			};
		};
	};
};
```

同时要在 dts 里把 `&camss` / `&csiphy0` 置 `status = "okay"`，并补 `csiphy0_ep` 端点
（camss 侧 endpoint 的写法参考 `sm8550.dtsi` 的 camss 节点与其它 qcom 机型 dts）。

### 2.4 上机验证（刷入后）

```bash
# 1) 驱动 probe
dmesg | grep -iE "ov13b10|camss|csiphy|cci"
# 2) I2C 是否真的有器件
i2cdetect -y <cci0_i2c0 对应总线号>   # 或用 dmesg 里的 i2c 总线号
# 3) media 拓扑
media-ctl -p -d /dev/media0
# 4) 抓一帧（先看 CSI 是否有数据；ISP 未通时至少要能拿到 subdev 与 format）
v4l2-ctl -d /dev/video0 --list-formats-ext
```

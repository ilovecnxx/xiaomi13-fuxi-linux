## 为什么必须源码构建

- Denial 官方二进制包只有 **x86-64**（Arch/CachyOS/Omarchy、Debian 13 trixie、
  Ubuntu 24.04 noble、Fedora 44、Alpine 3.24）。ARM64 是"完整支持但未发布官方二进制包"，
  官方指引是源码构建（`docs/BUILDING.md`、`CROSS_BUILDING.md`）。
- 本机手机是 **Ubuntu 26.10 arm64**，即使有 x86-64 包也不能用。
- 主机（x86_64, Ubuntu 26.10）根分区只剩约 21 GB，放不下固定版本 Flutter/Skia fork 的
  engine 构建树；手机 rootfs 有约 87 GB 可用，且 aarch64 原生构建是仓库一等支持路径
  （`tools/lib/denial-architecture.sh`，`DENIAL_ARCH=aarch64` / `DENIAL_FLUTTER_ARCH=arm64`）。
- 结论：**在手机内原生编译**，由 teammate `denial-builder` 执行；Lead 持有 agent 锁。

## 构建方案（手机原生 aarch64）

- 源码：`https://github.com/denialwm/denial`，固定到最新 release tag（构建产物记录 tag/commit）。
- 工具链：Rust 由 `rust-toolchain.toml` 固定（1.98.0），Flutter/Skia 由
  `prebuilt/flutter-engine/SOURCE_LOCK.json` 固定，`tools/denial-pc bootstrap` 拉取。
- 组件：`deniald`、`denialctl`、`denial-portal`、匹配的 `libflutter_engine.so`、
  dart shell bundle、settings bundle（mobile/desktop 两种场景由同一 bundle 提供，
  由 `DENIAL_SHELL_PROFILE` 选择）。
- 产物放工作区 `work/denial-arm64/`（被 .gitignore 忽略），手机侧构建日志落
  `work/claude-logs/denial-build-20261031/`。

## 集成方案（回退优先）

1. **安装前缀 `/usr/local`**：`denial-session` 按其自身路径推导前缀
   （`/usr/local/bin/denial-session` → bundle `/usr/local/lib/denial/flutter`），
   不占用 dpkg 包的 `/usr`，避免与 Ubuntu 包冲突。
2. **会话单元** `/etc/systemd/system/denial.service`（仿 `phosh.service`）：
   - `User=1000`、`TTYPath=/dev/tty7`、`TTYReset/VHangup/VTDisallocate`、`PAMName=login`；
   - `ExecStart=/usr/local/bin/denial-session`；
   - 环境：`DENIAL_SHELL_PROFILE=mobile`、`XDG_SESSION_TYPE=wayland`、
     `XDG_SESSION_DESKTOP=denial`、`XDG_CURRENT_DESKTOP=Denial`、`LANG=zh_CN.UTF-8`；
   - `Restart=always`、`Conflicts=getty@tty1.service`、`Before=graphical.target`；
   - `ExecStartPost=+chvt 7`（与 Phosh 一致，确保屏幕切到会话 VT）。
3. **互斥切换**：Phosh 与 Denial 都占 tty7/DRM master，同一时间只能跑一个。
   `scripts/fuxi-denial.sh` 提供：
   - `install` 把产物装到手机（不切换会话）；
   - `switch`：`systemctl stop phosh` → `systemctl start denial`（**不 enable**，
     重启仍回 Phosh，直到验证通过）；
   - `rollback`：`systemctl stop denial` → `systemctl start phosh`，并做只读检查；
   - `enable-default` / `disable-default`：确认后才把开机默认改成 Denial / 改回 Phosh；
   - `status` / `logs` / `shot`（grim 截图拉回主机）。
4. **输出配置**：先让 Denial 自动发现输出（不放 `outputs.conf` pin），跑起来后再根据
   实际画面决定缩放（1080x2400 物理像素；48 逻辑像素状态栏；移动外壳按逻辑坐标工作）。
   若画面比例不对，再写 `/etc/denial/outputs.conf`（`scale=DSI-1,2.5` 等）。
5. **Portal**：Denial 自带 `denial-portal`（Settings portal）与 `xdg-desktop-portal-wlr`
   （截图/录屏）。手机现有 `phosh-portals.conf` 只是 xdg-desktop-portal 的路由文件，
   切换后需要补 `xdg-desktop-portal` 配置，避免路由到已停的 Phosh portal。
6. **Xwayland**：装 `xwayland` 包（apt，arm64 可用）作为兼容回退；不阻塞首启验证。
7. **健康检查**：现有 `scripts/fuxi-health.sh` 检查 Phosh/phoc 进程与
   `mobi.phosh.OSK`——切到 Denial 后这些检查项必然失败，属预期；Denial 自己的检查用
   `denialctl status`、`journalctl -u denial`、`denial-session --check`。

## 回退方案

- 任意失败（黑屏/无响应/崩溃）：SSH 仍可用（WiFi/USB 与图形会话无关），执行
  `scripts/fuxi-denial.sh rollback` → 停 denial、起 phosh；若 systemd 状态异常，
  兜底 `systemctl start phosh.service` 并 `journalctl -u denial -b` 取证。
- 验证通过前不修改开机默认（不 `enable` denial、不禁用 phosh），重启自动回 Phosh。
- 用户可见状态通过 `grim` 截图（Denial 实现 wlr-screencopy）与手机屏幕双确认。

## 风险与边界

- **GPU/Impeller 未验证**：Adreno 740 mainline (freedreno) 跑 Denial 的 Impeller GLES
  后端是首次尝试；失败时用 `DENIAL_FLUTTER_RENDERER=skia` 回退（同引擎包内）。
- 移动外壳的蜂窝状态/SIM PIN/指纹等集成只在服务存在时显示；本机 ModemManager 为补丁版
  且当前 rmnet 未建数据会话，属既有问题，不阻塞桌面验证。
- 手机会因编译高负载发热，构建期间保持 USB 供电；不重启、不刷机。
- 当前设备仍在 #222 实验镜像上；按项目红线，实验结束应刷回 s2idle2 #207 并跑健康检查
  ——**需要用户确认后才能刷机/重启**，桌面验证完成后单独处理。
- 禁用 Phosh 会让 `fuxi-health.sh` 的 phosh 相关项失败（预期），报告时说明。

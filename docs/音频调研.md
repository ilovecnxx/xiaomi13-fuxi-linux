# 小米 13（fuxi）音频：调研与计划

最新验证：2026-10-29，见 `音频出声修复-20261029.md`。audio-probe4 / #172 两颗功放独立测试可听，
用户已确认普通用户 PipeWire 桌面四声短音均可听见；保护/标定仍未接入。
修复了 GENI I²C 漏编、SX 音量上限失效、声道映射和 speaker-only UCM；旧 audio1–4 不能替代此验收。

下文保留 2026-10-27 的硬件调研与历史方案。数据来源：运行中系统的 DTB（`work/device-info/fuxi-live.dts`）。

## 硬件

| 部件 | 厂商 DTB | 主线 |
|---|---|---|
| SoC 音频 | LPASS 数字宏 rx/tx/va/wsa/wsa2（`qcom,lpass-cdc-*-macro`），ADSP 上跑 AudioReach | `snd-soc-lpass-*-macro`、`q6apm`/`audioreach`、`qcom,sm8550-sndcard` |
| 编解码器 | `qcom,wcd938x-codec`（SoundWire 从设备 ×2：rx/tx）— 听筒、耳机、模拟麦克风 | `snd-soc-wcd938x`（+ `wcd938x-sdw`） |
| 扬声器功放 | 2× `cirrus,cs35l41`，I2C `0x880000`（主线 `&i2c8`，QUP `qupv3_id_1`）：`@40`（"B"，下扬声器，右声道，reset GPIO183、irq GPIO99）、`@42`（"T"，上扬声器兼听筒，GPIO68 切换，reset GPIO182、irq GPIO98）；boost 15 µF / 1000 nH / 4000 mA | `snd-soc-cs35l41-i2c`（属性名相同） |
| 数字麦克风 | 4× `qcom,swr-dmic` | VA/TX 宏 + SoundWire |
| 其他 | `wsa884x` 节点（大概是别的版本用的），`msm-ext-disp`（DP 音频） | — |

## 厂商声卡节点要点（`qcom,kalama-asoc-snd`）

- `qcom,tdm-audio-intf = <1>`、`qcom,sec-mi2s-gpios`、`qcom,tdm-max-slots = <4>`：CS35L41 走 **Secondary MI2S/TDM**
  （LPASS 是主，`qcom,msm-mi2s-master = 1`），最多 4 个时隙（两颗功放各占左右）。
- `asoc-codec-names`：`lpass-cdc`、`wcd938x_codec`、`swr-haptics`（振动马达也在 SoundWire 上）、`wsa-codec1/2`（未用，`qcom,wsa-max-devs = <0>`）。
- `qcom,msm-mbhc-usbc-audio-supported = <1>`：耳机走 USB-C 模拟音频（需要 USB-C 切换芯片 + pmic_glink 的 altmode/UCSI，
  与 M5.1 暂时没接的 USB-C connector 有关）。
- DMIC 0/1、2/3、4/5 三组引脚（`qcom,cdc-dmic*-gpios`）。

## 难点

1. **AudioReach 拓扑（.tplg）**：主线 SM8550 QRD/HDK 用 linux-firmware 的 `qcom/sm8550/*-tplg.bin`，对应 WSA884x 功放。
   本机扬声器是 CS35L41（走 I2S/TDM 而不是 SoundWire），需要自己写拓扑（audioreach-topology 的 m4 模板）：
   扬声器 → TDM/MI2S 后端（查厂商 `qcom,kalama-asoc-snd` 的 dai-link 确定是哪路接口与时隙）、
   听筒/耳机 → WCD938x RX（SoundWire）、麦克风 → TX/VA 宏。
2. **CS35L41 固件与调音**：Android `/vendor/firmware/` 里的 `cs35l41*.wmfw` / `.bin`（扬声器保护算法与调音参数），
   主线驱动按 `cs35l41-dsp1-spk-prot-<子系统 ID>[-<前缀>].wmfw/.bin` 命名加载，需要改名放到 `/lib/firmware/cirrus/`。
   没有调音文件时功放可以用"直通"模式先出声（音量要限制，保护扬声器）。
3. **ADSP 音频服务**：ADSP 已由 `fuxi-firmware-devices` 启动（M5.1），q6apm 走同一个 GLINK 通道。

## 计划（M5 之后）

1. 读厂商 sound 节点的 dai-link（TDM 号、时隙、mclk），确定 CS35L41 的接口；
2. DTS：`&i2c?`（0x880000 对应的主线节点）+ 两个 cs35l41、`&swr*`/`wcd938x`、`sound` 节点（`qcom,sm8550-sndcard`）；
3. 从 Android 只读复制 CS35L41 固件/调音；
4. 写拓扑，先通扬声器直通播放，再做听筒、耳机、麦克风；
5. 用户空间：PipeWire + WirePlumber（Phosh 自带），UCM 配置（alsa-ucm-conf 的 Qualcomm 模板）。

## 第一步已实现（10-27，待上机）：两个扬声器

- **接口确认**：厂商 `qcom,sec-mi2s-gpios` → `sec_tdm_pinctrl` → TLMM GPIO121（i2s1_sck）、122（i2s1_data0，功放回采）、
  123（i2s1_ws）、124（i2s1_data1，送功放）。主线对应 AudioReach `SECONDARY_MI2S_RX`、时钟 `LPASS_CLK_ID_SEC_MI2S_IBIT`。
  （`lpi_i2s2_*` 是 LPASS LPI 的另一组 I2S，功放没用它。）主线参考：`qcs8550-ayntec-common.dtsi`（AYN Odin2，Primary MI2S + 两个 aw88166）。
- **DTS** `sm8550-xiaomi-fuxi-audio.dts`：i2c8 + 两个 CS35L41（复位脚 GPIO_ACTIVE_HIGH，主线驱动置 1 = 解除复位）、
  i2s1 引脚、`q6apmbedai` dai@18、声卡 `xiaomi,fuxi-sndcard`（model `Xiaomi-13`）。
- **机器驱动补丁** `sound/soc/qcom/sc8280xp.c`：新 compatible `xiaomi,fuxi-sndcard`（driver_name 仍是 `sm8550`）；
  新标志 `codec_sysclk_bclk`：MI2S hw_params 里给每个 codec 设 DAI 与组件 sysclk = BCLK（CS35L41 的 PLL 以 SCLK 为参考，
  不设就没有时钟，Intel/联发科的 CS35L41 机器驱动也是这么做的）；顺带把 MI2S 的 codec 格式设置改成对所有 codec 生效（原来只设第一个）。
- **拓扑** `scripts/fuxi-audio-tplg.sh`：本机 linux-firmware 的 SM8550-QRD 拓扑（不联网）反编译 → Primary MI2S 通路改成 Secondary
  （DAI 18、HW_IF_IDX 1、SD_LINE_IDX 2 = SD1）→ 重新编译为 `qcom/sm8550/Xiaomi-13-tplg.bin`。
  alsatplg 1.2.15 反编译有个清单瑕疵，脚本里修掉了；重新编译的结果与原文件语义一致（已回读比对）。
- **构建**：`FUXI_DTB=sm8550-xiaomi-fuxi-audio scripts/fuxi-build-abl.sh audio1`（临时打开 SOUND/SND_SOC/QDSP6/SC8280XP/CS35L41/SOUNDWIRE），
  镜像 `abl-fuxi-audio4.img`。
- **上机**：`scripts/fuxi-m6-audio.sh`。功放直通（不加载 Cirrus DSP 固件）、数字音量 -20 dB、模拟增益最低，播两声 440 Hz；需要用户听。
  没声音时：先看 dmesg 里 cs35l41 是否 probe（I2C 地址/复位），再试 `SD=1`（数据线 SD0）。
- **之后**：WCD938x（耳机，USB-C 模拟音频需要 fsa4480 类切换芯片）、麦克风（TX/VA 宏 + DMIC）、听筒（T 功放 + GPIO68）、
  Cirrus 调音固件、UCM 配置。

## 第二步已准备（10-27，待上机）：WCD9385 麦克风/耳机 + UCM

- 厂商 DTB 里 WCD938x 接法与 SM8550 QRD 相同（复位 GPIO108、L15B/BOB1 供电、swr1/swr2 从设备 3/4），
  只有 micbias 是 2.75 V。数字麦克风引脚组在厂商 DTB 里全是 disabled → 麦克风都是 WCD 模拟输入（AMIC1..5）。
- DTS `sm8550-xiaomi-fuxi-audio2.dts`（include `-audio.dts`）：wcd938x、swr1/swr2、WCD Playback/Capture 链路；
  镜像 `abl-fuxi-audio3.img`（构建时另开 WCD938X_SDW、LPASS RX/TX/VA 宏、LPASS LPI pinctrl）。
- UCM：`work/rootfs-overlay/usr/share/alsa/ucm2/Qualcomm/sm8550/Xiaomi-13/`（+ `conf.d/sm8550/Xiaomi-13.conf`），
  复用 alsa-ucm-conf 自带的 wcd938x / qcom-lpass 片段：Speaker（hw:,0）、Headphones（hw:,1）、Mic1 = AMIC1、Mic2 = AMIC3（hw:,2）。
  哪个 AMIC 是哪个物理麦克风待上机确认（`scripts/fuxi-m6-audio.sh` 第 4 步会分别录音看峰值）。

## 第三步已准备（10-27）：听筒、功放 DSP 固件、振动

- **听筒**：厂商 T 功放的 `rcv_gpio_high/low`（GPIO68）= 上扬声器切到听筒模式。DTS 用 `simple-audio-mux`（aux-dev）把它暴露成
  ALSA 控件 `RCV MUX`（Speaker/Earpiece）；UCM 新增 `Earpiece` 设备（切 GPIO68、静音 B），与 `Speaker` 互斥。
  （控件名按 DAPM mux 规则推断为 "RCV MUX"，上机用 `amixer controls` 确认。）
- **功放 DSP 固件/调音**：DTS 加了 `cirrus,subsystem-id = "xiaomi-fuxi"`，主线找
  `cirrus/cs35l41-dsp1-spk-prot-xiaomi-fuxi-{B,T}.{wmfw,bin}`；`scripts/fuxi-cirrus-firmware.sh` 从 Android 只读拉取候选并改名放到
  `work/firmware-audio/cirrus/`。打开 `"B DSP1 Preload Switch"` 才加载；扬声器保护需要标定值（Android 里大概在 persist 的音频目录），
  没有标定前继续用直通 + 限音量。
- **振动马达**：厂商是 PM8550B 上的 `qcom,hv-haptics`（SPMI 0xf000），另有 SoundWire 上的 `pm8550b-swr-haptics`（音频触感）。
  主线没有 HV haptics 驱动 → 待写（输入子系统 ff-memless，先只做 DIRECT_PLAY 定时振动）。
- 镜像 `abl-fuxi-audio4.img` / `abl-fuxi-audio3.img` 已按上面重编。
- **音量保护（10-27 09:40 更正）**：CS35L41 的 `Digital PCM Volume` 控件范围是 0..913（每档 0.125 dB，816 = 0 dB，913 = +12 dB），
  之前 UCM 里写的 940 超范围，已改成 696（-15 dB）。机器驱动在 Secondary MI2S 链路初始化时把 B/T 数字音量上限限制在 816（0 dB），
  与主线对 WSA 功放的做法一致（没有 DSP 扬声器保护前不许放大）。audio1/audio2/full2 已重编。
  **10-29 实机更正**：上述旧限幅调用实际失败，已修正 ASoC 的 SX 范围检查并传播错误；
  新候选实际返回 max=816。0 是静音，1 才是 -102 dB；816 略低于 0 dB，当前测试值 497 为 -40 dB。
- **振动马达参数（厂商 DTB `qcom,hv-haptics@f000`，PM8550B）**：寄存器块 0xf000/0xf100/0xf200（cfg/ptn/?），中断 fifo-empty，
  LRA 谐振周期 5882 µs（≈170 Hz，f0 校准范围 0xa0..0xb9），vmax 1200 mV（各效果 3600 mV），刹车模式 1 / 图样 ff 3f 1f，
  标定数据在 SDAM（nvmem `hap_cfg_sdam`）。缺寄存器定义：需要小米开源内核（`qcom-hv-haptics.c`）作参考，
  本机没有离线副本——待用户同意从 GitHub（MiCode/Xiaomi_Kernel_OpenSource 的 fuxi 分支）取源码后再写主线驱动。

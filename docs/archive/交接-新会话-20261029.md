## 1. 项目目标与技术栈

**目标**：在 Xiaomi 13（代号 fuxi，SM8550 / Snapdragon 8 Gen 2）上运行主线 Linux + 完整手机/桌面用户空间，逐步达到日常可用。
用户设定的顺序：先基本功能（显示/触控/桌面 → WiFi/蓝牙/USB → 音频/通话 → 供电/温控 → 相机/媒体），高级驱动后做。
不使用 Android vendor kernel、Halium 或 Android HAL。M5 验收标准见 `docs/目标-M5.md`（拔线开机、电量与真实充电、WiFi 上网 + WiFi SSH、Phosh 触控、普通重启回 Android）。

**技术栈与启动链**
- 内核：`build/linux/`，主线 7.3（HEAD `5b0764a53` drm-next 2026-10-21 合并）+ **大量未提交的本地改动**（不要 reset/checkout）。
- 引导：ABL → `recovery_b`（boot.img v1：Image.gz + 厂商 fuxi DTB 作“诱饵”）；`CONFIG_FUXI_FORCE_BUILTIN_DTB` 忽略 ABL 的 DTB，
  改用编进内核的主线 DTB；**内核 cmdline 来自该 DTB 的 `/chosen/bootargs`**。initramfs 内建，8 秒后 switch_root 到 sda33。
- 根文件系统：Ubuntu 26.10（代号 stonking），`linux` 分区 sda33；桌面 Phosh + phoc（wlroots）、Stevia 屏幕键盘、PipeWire/WirePlumber、NetworkManager。
- 普通开机 = Android 16（Xiaomi OS3.0.307.0，slot `_b`，adb 产品名 lineage_fuxi）。

**关键工具**
- `tools/platform-tools/adb`（系统 PATH 里没有 adb/fastboot）。
- `scripts/fuxi-build-abl.sh <名字>`：用 `FUXI_DTB=<dts 名>` 选设备树；默认 `FUXI_PM=1`（调频/温控，含 `DEVFREQ_THERMAL`）；
  变体名以 `-audio-disp` 结尾才会套用显示 + 音频配置；产物 `work/kbuild/abl-fuxi-<名字>.{img,config,dtb,build.json}`；构建后恢复主 `.config`。
- `FUXI_KEEP=1 scripts/fuxi-test-recovery.sh <img> '<ssh 命令>'`：手机须在 Android（若在 Linux 会先 ssh 重启回 Android），adb root 把镜像 dd 进
  recovery_b 并回读校验，`adb reboot recovery` 进 Linux。**会重启手机并写 recovery_b**。
- `scripts/fuxi-ssh.sh`：USB SSH（手机 10.42.0.2）；`FUXI_HOST=10.10.10.43 scripts/fuxi-ssh.sh` 走 WiFi。
- Linux 内重启回 Linux：`systemctl reboot --reboot-argument=recovery`；普通 `reboot` 回 Android。
- 只读验收：`scripts/fuxi-health.sh [--require-wifi] [--require-sensors]`；显示快照 `scripts/fuxi-display-snapshot.sh`。
- 主机回归：`python3 -m unittest discover -s scripts/tests`（当前 42 项通过）。

## 4. 已解决的问题与仍存在的问题

### 已解决（根因已证实）
1. **GPU ZAP `-22`**：`/vendor/firmware/a740_zap.mdt/.b02` 是高通 SecTools “General Use Test Key (for testing only)” 签名，量产 TZ 拒绝；
   Android kgsl 实际用 `/odm/firmware/a740_zap.mbn`（ueventd 在 /odm 找到），`/odm/firmware/a740_zap.mdt` 为 “Xiaomi Secureboot” 签名，b00/b01 两版逐字节相同。
2. **桌面慢**：Pixman 软件合成 phoc 吃满单核；改 GLES 后解决。
3. **120 Hz**：厂商 timing@1 与 timing@0 porch、1.1 GHz 面板时钟、7.3 ms transfer-time 相同；DSI lane rate 固定 1.1 Gbit/s，命令模式一帧 DSC 约 4.7 ms < 8.33 ms。
4. **GPU cooling 未注册**：缺 `DEVFREQ_THERMAL`（sm8550.dtsi 已有 GPU 热区 cooling-maps）。
5. **拔线后外网会断**：usb0 默认路由 metric 0 抢在 WiFi(600) 前。
6. **管制域一直 US**：ath12k self-managed 需 `ATH_REG_DYNAMIC_USER_REG_HINTS`；且 cfg80211 在 initramfs 读不到 regulatory.db 缓存 `-ENODATA`，须先 `iw reg reload`。
7. **熄屏时设亮度报错**：见面板驱动修复。
8. **只开 cpuidle 不省电**：`HZ_PERIODIC` HZ=250 每 4 ms 唤醒，集群最小驻留 9.1 ms；改 NO_HZ_IDLE。
9. **PipeWire 只有 Dummy Output（WCD 变体）**：录音 PCM hw:,2 只接受 2ch S16_LE 48 kHz，UCM 写 1 声道导致 ACP 判整个 HiFi profile 不可用。
10. **WCD 版 UCM 扬声器电平是旧值 696/0**：同步为用户确认可听的 577/5。
11. **sync_state 永远挂起**：QCE(1dfa000)、ICE(1d88000) 无驱动、GMU 不绑定驱动 → GCC、GPU_CC、两个 interconnect 永不 sync，互连带宽保持最大。
    无模块内核下 `fw_devlink_probing_done()` 在 late_initcall 运行时这些提供者挂在暂停期的 deferred_sync 链表而被跳过，所以必须 `deferred_probe_timeout=30` 让超时任务在 31.7 s 再跑一次。

### 仍存在 / 未完成
- **M5 第 1 项**：拔 USB、音量上+电源开机进 Linux——需人手。
- **M5 第 2 项**：墙充（DCP/PD）真实充电——需人手；电脑 USB 只协商 SDP（5.07 V × 353 mA），亮屏负载下净放电。
- **SoC 级睡眠**：`qcom_stats` 的 cxsd/aosd/ddr Count 一直 0（USB 常插使 USB 控制器保持 CX）；需拔线或软断开验证。
- **系统挂起 s2idle**：当前内核未开 `SUSPEND`/`PM_SLEEP`（`/sys/power/state` 为空）；历史 `-sleep` 变体（`sm8550-xiaomi-fuxi-sleep.dtsi`）从未上机。RTC `rtc-pm8xxx` 存在。
- **第二麦克风**：UCM Mic2（AMIC3→ADC2→SWR_MIC1→DEC0）无信号；扫描 ADC3/INP4、ADC4/INP5 组合也无独立信号（ADC3+SWR_MIC0 疑似与 ADC1 串扰）。
  机器驱动 `sound/soc/qcom/sc8280xp.c` 把 TX_CODEC_DMA 后端固定为 1 声道，只有 DEC0 进 DMA。需对照厂商 TX 端口映射。
- **耳机**：MBHC 开机报 “Impedance detect ramp error”（USB-C 模拟音频无 FSA4480 切换），未验收。扬声器保护/标定未做。
- **蓝牙耳机配对 + A2DP 出声**、**5 GHz 连接**（当前 AP 在 2.4 GHz）、小米 WiFi RF 标定（仍用参考板 board data）未做。
- **屏幕旋转与传感器方向**需转动手机；90 Hz/动态刷新率未实现（启动参数固定）。
- 相机、基带/通话/短信、指纹、振动未做。
- `qcom_battmgr` 每 10 s 报 “unknown message 0x50”（未处理，噪声）。

## 5. 已尝试但失败 / 无效的方案（不要重复）
- 只开 cpuidle、保留周期节拍（idle1/#192）：熄屏电流 128 mA，比关闭时还略高，集群 usage 0。
- 只加 `fw_devlink.sync_state=timeout`（ru4sync/#198）：无效，4 个提供者仍 `state_synced=0`，日志无 “Forcing”。
- 去掉 `pd_ignore_unused`/`clk_ignore_unused`（#196/#197）本身对电流无可见收益（在误差内），收益来自强制 sync_state。
- HTTPS 测试用 `source_address` 绑定无线 IP：路由按目的地走 usb0，被拒；必须 `SO_BINDTODEVICE b"wlp1s0"`。
- logind `SetBrightness` 用 `session/auto`（runuser 会话无 seat）被拒；要对 seat0 会话（`loginctl` 中 fuxi/seat0）调用。
- `iw reg set CN` 不先 reload：静默无效。
- 健康脚本统计“开着但未用的时钟”用 `clk_hw_enabled`：本内核 debugfs 无此文件，结果为 0 不可信；改读 `clk_summary`。
- 在 1 MB/s 级别下载测试：ubuntu-ports Contents 路径 404；tuna 镜像无 User-Agent 403；需 `User-Agent: Debian APT-HTTP/1.3`（`.../dists/stonking/universe/binary-arm64/Packages.xz` 200，11.1 MB / 5.5 s）。
- 第二麦克风 AMIC3/AMIC4/AMIC5 扫描（`work/claude-logs/mic-scan-20261029.log`）。

## 8. 必须遵守的开发要求
- **只写 `linux` 分区（sda33）和 `recovery_b`**；Android 系统与固件分区只读（固件从 Android 只读复制）。不回锁 bootloader，不改 GPT 槽位/active 位，
  不擦写 `persist`、`modemst1/2`、`fsg`、`fsc`。
- 刷机只用 `scripts/fuxi-test-recovery.sh`（不依赖 fastboot）；写入后必须回读哈希。测试镜像起不来：长按电源 20 秒回 Android。
- 不要 unbind/rebind 半初始化的 ath12k（会卡死整机）。内核 cmdline 不要加 `console=ttyGS0`。
- 不要 reset `build/linux`；主 `.config` 改动要留副本。变体选项若依赖不满足会被 olddefconfig 悄悄丢掉，构建脚本会核对 `-e` 选项。
- 改动先在主机完成构建与静态检查，再集中上机；每次上机后跑 `scripts/fuxi-health.sh --require-wifi --require-sensors`。
- 数字状态（connector connected、截图、sysfs 读数）不能代替用户的物理确认；画面、声音、触控以用户反馈为准，并如实记录。
- 不读取/输出 WiFi 口令；本机无线/蓝牙地址只存 `work/device-info/radio-addresses.txt`，不发布。
- 从 Android 拉的固件要先核签名：`strings x.mdt | grep -iE "xiaomi|test key"`。
- 每完成一步更新：`docs/进展-20261029.md`、`docs/目标-M5.md`（或对应专题文档）、`README.md` 状态、`work/state/current-device.json`。
- 用户偏好（Stop hook 指示）：不要停下等确认，按 `docs/目标-M5.md` 与最终目标持续推进；需要物理操作时先做不依赖手机的开发；遇到问题自行绕过并记录。
  但用户可能随时中断——中断后先汇报状态，不要擅自继续被拒绝的操作。
- 回复用户用中文。

## 用户确认与边界

- 用户先明确反馈“没听到声音”，因此将问题从未确认改为实际无声排查。
- 调整测试增益后，T 功放单独启用、B 静音的重复测试得到反馈：**“顶部2声”**。
- B 功放单独启用、T 静音时，反馈：**“听到了，但位置不确定”**。
  因此两颗独立功放路径都有可听输出；底部位置和声学隔离仍不做过度断言。
- 使用普通 fuxi 用户的 PipeWire 桌面通路、左右分开的四声短音，反馈：**“四声都听见了”**。
- 这是基本出声与播放通路验证，不是最大音量、音质、扬声器保护、麦克风或通话验收。

## 定位过程

1. 保持两颗功放数字静音，分别发送全零 PCM 与 440/880 Hz 测试数据。
   从 TLMM debugfs 读取输入采样，GPIO121/123 的时钟均在运行；GPIO124 在零数据期间
   702 次全低，在测试波形期间 360 次低、342 次高。GPIO122 保持低。
   证明 SD1 输出随数据变化，不是只有时钟没有数据；异步采样不能代替逻辑分析仪解码。
2. 临时重启 Android，只读复制原厂 mixer XML、保护固件与 B/T 系数，读取功放配置。
   debugfs 临时以只读挂载并在返回 Linux 前卸载；没有修改 Android 音频配置、固件或真实 persist。
3. 原厂 XML 的直通 `handset` 路径采用 ASP、模拟增益 raw 5；原厂扬声器路径采用保护 DSP，
   模拟 raw 18、数字 raw 817。本项目原直通测试则为数字 raw 497（-40 dB）、模拟 raw 0。
4. 桌面显示音量 0.40 时，PipeWire 实测 `channelVolumes=[0.063997, 0.063997]`，
   相当于另加约 -23.88 dB 软件衰减。它和很低的硬件增益叠加，使桌面输出接近不可听。
5. 对照测试采用数字 raw 577（-30 dB）、模拟 raw 5，1 kHz、半幅、20 ms 淡入淡出短音。
   每个脉冲 0.75 秒，间隔 0.5 秒；独立测试总计 2.5 秒，左右顺序测试总计 5 秒。
   测试后均恢复原控件，未出现功放故障位。取得用户听音确认后再持久化工作设置。

## 已部署的修复

- 两个 speaker-only UCM 文件中的 B/T 默认与启用设置统一为数字 raw 577、模拟 raw 5。
  DisableSequence 仍将数字音量清零。内核 max=816 限制保持生效，没有改成原厂高增益。
- 桌面软件音量设为 1.00，实测通路不再额外衰减；实际输出仍由 UCM 的低硬件增益限制。
  用户之后降低桌面滑块仍会正常衰减，但本阶段可能较快变得难以听见。
- 重启 PipeWire/Pulse/WirePlumber 后，桌面软件音量仍为 1.00，两颗功放读回仍为 577/5。
- `fuxi-audio-smoke.sh --tone` 改为已验证的五秒半幅淡入淡出短音；静音模式仍只发送零数据。
- `fuxi-audio-diagnose.py` 和测试同步使用新的工作增益。M6 部署脚本仅在默认输出确为本机
  speaker sink 时设置软件直通音量，不修改其它输出设备。
- 用户空间修复完成后没有再次重启整机；已验证音频服务重启保留配置。
  本轮早些时候的 Android → Linux 往返验证了已有 RTKit 的启动恢复。

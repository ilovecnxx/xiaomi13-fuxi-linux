# Chromium 浏览器移植到手机（2026-10-30）

用户要求“移植一个谷歌浏览器到手机里面”。本文件记录方案、实施、验收与回退。

## 结论与方案

- **Google Chrome 官方没有 arm64 Linux 版**（官方只发 x86-64/Windows/macOS）。
  手机是 Ubuntu 26.10 **arm64**，因此采用与 Chrome 同一内核的开源 **Chromium**
  （Debian `bookworm` arm64 打包，当前 **150.0.7871.100**）。
- 安装方式为**隔离前缀 `/opt/chromium`**，**不经过系统 dpkg**、不改系统共享库，
  可整体删除回退；运行在现有主线 Linux + Phosh（Wayland）桌面上，作为普通桌面应用。

## 关键难点与解决

1. **Ubuntu 26.10 只有 snap 转换包**：`chromium-browser` 是指向 snap 的过渡包，
   而手机没有 snapd（也不适合在主线上跑 snap）。→ 改用 Debian 原生 `.deb`。
2. **glibc 兼容**：手机 glibc 2.44，Debian bookworm 的 chromium 针对 2.35 构建，
   新版 glibc 向后兼容旧二进制，可直接运行。
3. **依赖 soname 缺口**：Debian chromium 依赖 7 个 Ubuntu 26.10 里没有对应 soname 的库
   （其余依赖 Ubuntu 已用 `t64` 包名提供同名 `.so`）：
   `libdav1d.so.6`、`libdouble-conversion.so.3`、`libFLAC.so.12`、`libjpeg.so.62`、
   `libminizip.so.1`、`libopenh264.so.7`、`libXNVCtrl.so.0`。
   → 从 Debian 对应 `.deb` 解出这些 `.so`，放到 `/opt/chromium/privatelib`，
   启动脚本用 `LD_LIBRARY_PATH` 让私有库**优先于**系统库。实测 `ldd` 无 `not found`。
4. **渲染路径**：Chromium 150 的 ANGLE 默认先试 Vulkan（wayland 下不兼容，报
   `vkCreateInstance() failed -9` 后回退）。启动参数固定
   `--ozone-platform=wayland --use-angle=gl --use-gl=angle --disable-features=Vulkan`，
   最终 **GPU 进程映射 `libEGL_mesa`（freedreno / Adreno 740 硬件 GL）**，非 SwiftShader。
   若 GPU 路径出问题可用 `CHROMIUM_SOFTWARE=1` 强制软件渲染。
5. **沙箱**：嵌入式环境用 `--no-sandbox`（标准做法）；另有 `--disable-dev-shm-usage`。

## 实施（已实机完成）

镜像/内核：主线 Linux `7.3.0+ #209`，Ubuntu 26.10，Phosh 会话，USB（10.42.0.2）与 WiFi
（10.10.10.43）均可 SSH。

- 下载并**校验 SHA256** 的 Debian bookworm arm64 包：`chromium`、`chromium-common` +
  上述 7 个私有库。缓存于主机 `work/chromium-debs/`。
- 解包到手机：
  - `/opt/chromium/root/usr/lib/chromium/chromium`（真实二进制，约 264 MB）
  - `/opt/chromium/root/usr/lib/chromium/*.pak`（chrome-common 资源）
  - `/opt/chromium/privatelib/*.so*`（7 个私有 soname）
- 启动器 `/opt/chromium/bin/chromium-launch`（注入 `LD_LIBRARY_PATH`、Wayland/ANGLE 参数）。
- 桌面项 `org.chromium.Chromium.desktop`：`Name[zh_CN]=Chromium 浏览器`，
  已装到 `/opt/chromium/share/applications/` 与 `~fuxi/.local/share/applications/`，
  并注册为 **https/http 默认处理程序**（`gio mime x-scheme-handler/https` →
  `org.chromium.Chromium.desktop`）。图标用包内 chromium.png。

## 验收证据

- `chromium --version` → `Chromium 150.0.7871.100`。
- `--headless=new --dump-dom https://example.com` → `<title>Example Domain</title>`（HTTPS 经系统根证书正常）。
- 图形窗口（Phosh Wayland 下 `gio launch` 桌面项）：9 个进程，GPU 进程映射 `libEGL_mesa`（硬件 GL）。
- 屏幕截图（`grim`，1080x2400）像素分析：`about:blank` 白页、example.com、新标签页均正确渲染；
  example.com 截图有黑字 + 蓝色链接色，非空白。
- 主机回归：`python3 -m unittest discover -s scripts/tests` **52 项全过**（新增 7 项针对本脚本）。

## 可重复执行

```bash
# 部署 / 更新（手机已跑 Linux；走 WiFi 时加 FUXI_HOST=10.10.10.43）
scripts/fuxi-chromium-deploy.sh

scripts/fuxi-chromium-deploy.sh --rollback
```

部署脚本幂等：先校验 SHA256，再 scp（带重试，容忍 USB 抖动），`dpkg-deb -x` 解包，
用 `ldd` 校验无缺失库后写启动器与桌面项；只写 Linux rootfs（`/opt`、fuxi 的
`~/.local`、`/tmp`），不刷机、不重启、不动系统包。

## 已知限制 / 待用户现场验收

- 需用户在手机屏幕上**实际点开“Chromium 浏览器”图标**，确认窗口出现、能触屏滚动、
  地址栏可输入、能打开真实网页（本轮已用截图与进程状态佐证渲染，但按项目规矩以用户物理反馈为准）。

- 屏幕空闲熄屏时截图会全黑（DPMS off），非崩溃。

# 移动端 UI 层（2026-10-30 追加）

用户反馈：Chromium 默认是**桌面布局**，6.7 寸竖屏上地址栏/标签/菜单按电脑端排布，难用；要求**原生移动布局、模仿 iOS/安卓浏览器、保留 Chromium(Blink) 内核**。

## 关键技术判断

- Chromium 桌面版在 Linux 上**没有移动 UI**；安卓版 Chrome 的界面依赖 Android 系统框架，Linux 上拿不到。要 Blink + 原生移动布局，只能**自研外壳**。
- 手机上可嵌入的 WebView 只有 WebKitGTK（无 CEF/Qt WebEngine/Electron），所以“套壳换内核”不成立；正解是**在 Chromium 内注入移动端控制层**。
- 方案：Chromium 以 `--app` 无边框窗口跑页面；通过 CDP `Page.addScriptToEvaluateOnNewDocument`
  向每个页面注入**自绘的安卓-Chrome 风格外壳**（顶部圆角地址药丸、底部 5 键工具栏：后退/前进/主页/标签/菜单）。
  **导航/前进/后退/刷新/主页全部由注入的页面内 JS 用 history/location 完成**，不依赖外部 bridge，
  因此即使守护进程退出浏览器也照常可用。

## 实现文件（`work/chromium-mobile/`）

- `mobile-chrome.js`：自包含移动外壳（Material 风格；白顶栏 + 白底栏 + 圆角地址框 + 菜单/标签页底部抽屉）。
- `fuxi-mobile-shell.py`：**自愈守护**。启动 Chromium、持有单一 CDP 连接（全局锁串行化），
  后台 supervisor 线程在 CDP 断开/页面重载时自动重连并重新注入；进程退出自动重启。
- `cdp.py`：无第三方依赖的裸 WebSocket CDP 客户端（手机无 websocket-client）。
- `probe.py` / `selftest.py`：经 9223 bridge 的只读检查与点击自测。
- `launch-mobile.sh`：桌面会话里启动（幂等）的入口。
- `scripts/fuxi-chromium-mobile-ui.sh`：主机一键部署/回退，安装 **systemd --user 服务**
  `fuxi-mobile-chromium.service` + `~/.config/autostart` 自启 + 桌面图标 `Chromium 浏览器`，
  并注册为 https 默认程序。**跨重启持久**（服务在每次开机 Phosh 会话自启）。

## 验收证据（实机，内核 #207）

- `systemctl --user is-active fuxi-mobile-chromium.service` → **active**。
- bridge `/state` → `{"u":"https://www.example.com/","t":"Example Domain","b":true}`。
- `/eval` 覆盖层检查 → `{top:true, bottom:true, btns:5, addr:"www.example.com"}`（顶栏+底栏+5 键均在）。
- 点击“主页”按钮 → 执行成功、状态回到主页。
- CDP 页面截图（=Blink 实际渲染）分区取样：顶栏 `#f1f3f4` 地址药丸 71.6%、页面浅灰 238 占 89%、
  底部白工具栏 94.7% —— 与安卓 Chrome 观感一致。截图见 `work/claude-logs/chromium-20261030/ui-final.png`。
- 主机回归 57 项全过（新增 5 项）。

## 部署 / 回退

# 再叠加移动 UI 层（幂等）：

## 已知限制

- 物理屏幕实际画面受 Phosh 顶层状态栏影响；CDP 截图为准的渲染验证已通过，仍需用户**手指点开**确认触控手感。
- `--app` 单窗口，多标签以 `window.open` 简化（非真正的标签管理器）。
- 桌面版引擎访问部分站点可能仍按桌面 UA 渲染（未强制移动 UA）；如需可加 `--user-agent` 移动 UA。

## 图标去重与单实例（2026-10-30 追加）

- 之前有两个同名“Chromium 浏览器”图标：浏览器本体留下的桌面版 `org.chromium.Chromium.desktop`
  （`Exec=/opt/chromium/bin/chromium-launch`，无移动 UI）和移动 UI 版 `org.chromium.ChromiumMobile.desktop`。
  **已删除旧的桌面版图标，只保留移动 UI 版**；https 默认也指向 `org.chromium.ChromiumMobile.desktop`。
- 启动入口统一：`launch-mobile.sh` 改为调用 `systemctl --user start fuxi-mobile-chromium.service`
  （单一所有者），避免开机时 autostart 与 systemd 服务**双启动抢 9223 端口**（`Address already in use`）导致服务 inactive。

## 顶部英文提示条去除 + 速度（2026-10-30 追加）

- 现象：浏览器顶部一直有一条**深灰底英文提示条**，且观感“很慢”。
- 定位：实际屏幕像素分析（1080×2400）显示 y≈80–170 整段为 `(53,53,53)` 深灰 + 英文文字块，
  在地址栏之上、页面之上——是 Chromium 因启动参数 `--no-sandbox` 弹出的
  **“You are using an unsupported command-line flag: --no-sandbox…” infobar**。
- 修复：启动参数加 **`--test-type`**（Chromium 官方用于抑制此类 command-line 警告条）。
- 验证：修复后同一位置 y=80 起直接是白色地址药丸 `#f1f3f4`，深灰英文条消失；覆盖层 top/bottom 仍在。
- 速度实测：服务冷启动到页面可交互约 **1.9s**；打开百度首屏约 **0.66s**——并不慢；
  此前的“慢”主要来自该 infobar 的反复重排与视觉干扰，已消除。
- 备注：导航到新页面的那一刻有极短的一瞬（新文档注入完成前）工具栏空窗，注入完成后即恢复。

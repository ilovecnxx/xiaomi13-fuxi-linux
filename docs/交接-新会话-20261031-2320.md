## 4. 关键技术结论

### 4.1 蜂窝（结论固化，别推翻重来）

- **IMS PDN 是唯一卡点**：AP 侧 `WDS Start Network`（profile 4 / `apn=IMS` / ip 4/6/双栈）一律
  `InvalidOperation`；NM 用 `apn=IMS` 能起承载，但基带不当作 IMS PDN（imsa 仍 0，短信仍 53）。
- **CS 附着不可用**：`voice_domain=CS_PREFERRED` + 仅 LTE + 重启后仍 `CS: detached`，
  说明这张卡/这个网络没有 SGs（2G/3G 退网）。→ **短信也只能走 SMSoIP，和 VoLTE 同一个卡点**。
- 数据通路本身是好的：modem16 #222 上 3gnet + IPA 下行两轮实机通过。
- 方向：要么拿到 QMI 规范里 `Start Network Interface` 的 APN type TLV，要么抓 Android/NM 的真实请求字节。

### 4.2 相机（今天新开，进展到 probe）

- 四摄型号：cam0 IMX800（无主线驱动）、cam2 **OV13B10（有驱动，先打通）**、cam1 OV32C、cam3 S5K3K1。
- 已有基础：CAMSS 支持 sm8550、csiphy 驱动在、fuxi 相机 dtsi 有电源树+CCI、`fuxi-camera-power` 驱动在。
- 今天做了：开媒体配置（`MEDIA_SUPPORT`/`V4L_PLATFORM_DRIVERS`/`VIDEO_QCOM_CAMSS`/`VIDEO_OV13B10`）、
  给 ov13b10 加 OF 匹配表、DTS 接 OV13B10（CCI0 主机0 / MCLK1 / reset GPIO117 / CSIPHY0）。
- 实测 `#223`：`ov13b10 0-0010` 被 probe（I2C 0x10 正确），报 link-freq 560 MHz 不支持（DT 写了 400 MHz）。
- 实测 `#224`（560 MHz）：过了 link-freq 检查，卡在 **`failed to find sensor: -5`**（读 chip ID 失败）。
  同时 `/dev/media0`、`/dev/video*` 已出现（CAMSS/CSIPHY 侧起来了）。

## 5. 已尝试并失败（不要重复）

1. `qmicli`/GI 直接起 IMS 承载：profile 4、`apn=IMS`、ipv4、ipv6、双栈 —— 全部 `InvalidOperation`。
2. `bind_mux_data_port`：mux 0/1 × EMBEDDED/HSUSB/PCIE/HSIC/BAM_DMUX —— 全部 `QMI protocol error (3) Internal`。
3. `--dms-set-operating-mode=offline` 后再 `online` —— `InvalidTransition` 卡死，`dms-reset`/`mmcli --reset` 都没用，
   **只能重启**。以后切射频一律用重启。
4. NM 用 `apn=IMS` 起承载后：imsa 仍 0、短信仍 `NetworkNotReady(53)`。
5. `voice_domain=CS_PREFERRED` + 仅 LTE：CS 仍 detached。
6. 发短信：5G SA 下 `NetworkNotReady(53)`；仅 LTE 下 MM 超时（均未投递，未扣费）。
7. 抓 NM 的 QMI 报文：NM 无 QMI 日志域、libqmi 无 `G_MESSAGES_DEBUG=QMI` 输出、设备无 strace/tcpdump。
8. `fuxi-flash.sh status` 曾按 `min(分区,12MiB)` 截取算哈希导致「未知镜像」误报（已修，改为按镜像大小比对）。

### PPS 顺序核对

厂商初始化表的 DCS `0x9e` 载荷含 2520 行；厂商随后会按活动模式生成并发送完整 PPS。Linux 面板也先发送厂商初始化表，再通过标准 MIPI PPS packet 发送由 `drm_dsc_config` 打包的参数。MSM DSI bridge 的 `pre_enable` 先于面板 `prepare` 执行，`dsi_timing_setup()` 会先依据活动模式填充 DSC RC 参数；因此当前代码发送的 PPS 会使用活动模式的 2400 行配置。2520 与活动模式 2400 的差异本身不足以证明故障，当前不据此改值。

进一步核对了 Linux 的实际调用顺序：`dsi_mgr_bridge_pre_enable()` 调用 `msm_dsi_host_power_on()`，后者在启用 DSI controller 前调用 `dsi_timing_setup()`；该函数用活动 mode 更新图片宽高，再经 `dsi_populate_dsc_params()` 填充 RC 参数。面板桥设置 `prepare_prev_first`，使 DSI host 的 pre-enable 在面板 prepare 前完成；面板随后才在 `xiaomi_fuxi_on()` 中调用 `drm_dsc_pps_payload_pack()` 并发送 PPS。因此 probe 阶段尚未填充的 RC 字段会在发送前计算，不能把结构体最初的零值当作运行时 PPS。源码检查没有支持对 PPS 初始化作盲目改动；实物显示根因仍未确定。

### 厂商参数二次对照

再次逐项核对了候选驱动与原厂 `panel-m3-38-0c-0a.dtsi`：两者均为 1080×2400；水平前/同步/后沿为 124/32/124，垂直为 128/24/132；60 Hz 对应约 219.014 MHz DRM 像素时钟。DSC 均为 8 bpc、8 bpp、两个 540×40 slices，单包传输两片；候选 1.1 Gbit/s lane rate 与原厂 timing 的 1.1 GHz panel clockrate 相符。GPIO86 配置为 `mdp_vsync`，DPU 未显式指定 `qcom,te-source` 时默认选 GPIO0/`mdp_vsync_p`，与该脚用途一致。厂商 60/90/120 Hz 初始化差异仍由三条已核对的寄存器命令选择；没有证据支持再猜测修改 porch、DSC 或 lane rate。

# 小米 13（fuxi）蜂窝网络：调研与计划

更新：2026-10-27。

## 主线现状（sm8550.dtsi 已有）

| 部件 | 节点 | 固件（主线默认名） |
|---|---|---|
| 基带 Q6（MPSS） | `remoteproc_mpss`（`qcom,sm8550-mpss-pas`，内存 mpss/q6_mpss_dtb/mpss_dsm） | `modem.mbn` + `modem_dtb.mbn` |
| 数据通道 IPA v5.x | `ipa`（`qcom,sm8550-ipa`） | `ipa_fws.mbn` |
| 远程文件系统共享内存 | `rmtfs_mem`（0xd4a80000，2.5 MB） | — |

本机这几段保留内存（mpss 0x8a800000、q6_mpss_dtb 0x9b000000、mpss_dsm 0xd4d00000）与运行中 DTB 一致（M5 已核对）。

## 固件来源（全部只读取自手机自己的 modem 分区 `image/`）

`modem.mdt` + `modem.bNN`、`modem_dtb.mdt` + `.bNN`、`ipa_fws.*`，放 `/lib/firmware/qcom/sm8550/xiaomi/fuxi/`，
DTS 里 `firmware-name` 指过去（mdt 分段格式主线直接支持，同 ADSP）。
运营商配置 `mcfg_*.mbn` 在 modem 分区 `image/modem_pr/mcfg/`，由 tqftpserv 提供给基带。

## ⚠️ 基带数据分区（IMEI、射频校准）

`modemst1`、`modemst2`、`fsg`、`fsc` 存着 IMEI 和射频校准，基带通过 rmtfs **会写入**它们。
已有备份（`backups/20261024-172623/`），但：

- **rmtfs 一律用文件模式**（`rmtfs -o <目录>`），目录里放这几个分区的副本，主线下基带只写副本，真分区不动；
- 副本由 Android 下只读 dd 生成（或直接用 10-24 的备份）；
- 等确认稳定、并征得用户同意后，才考虑让 Linux 直接用真分区（否则 Linux 和 Android 两边的 EFS 状态会分叉，
  但不会损坏 Android 那边的数据）。

## 用户空间

- `rmtfs`（文件模式）、`tqftpserv`、`qrtr` 工具、`pd-mapper`（主线已有内核 PD mapper：`CONFIG_QCOM_PD_MAPPER`）；
- ModemManager + libqmi：SIM、短信、数据（IPA + rmnet：`CONFIG_QCOM_IPA`、`CONFIG_RMNET`）；
- 通话：国内 4G 需要 VoLTE（IMS），主线手机普遍还不支持 → 通话放到最后，先做短信与移动数据。

`USB_NET_QMI_WWAN`（不需要，基带不走 USB）。

## 已实现（10-27，待上机）

- 内核：`QCOM_IPA=y`、`RMNET=y`（主配置）；变体 DTS `sm8550-xiaomi-fuxi-modem.dts`；镜像 `abl-fuxi-modem3.img`。
- IPA 内建：initramfs 阶段 request_firmware 失败 → probe 失败、设备未绑定 → `fuxi-firmware-devices` 在根文件系统上 bind 一次
  （与 WiFi 同样的办法；IPA 失败路径是干净的，不是半初始化）。
- rmtfs 保留内存：主线固定在 0xd4a80000（厂商 DTB 是动态分配 `qcom,sharedmem-uio`），地址由 rmtfs 通过 QMI 告诉基带，固定地址没问题。
- rmtfs 文件模式 drop-in、部署脚本 `scripts/fuxi-m5-modem.sh`（见 `docs/目标-M5.md`）。
- 已在电脑上核对 Ubuntu 包（只下载解包看，未安装）：
  - rmtfs 1.3：发行版 `rmtfs.service` 是 `rmtfs -r -P -s`（直接用分区，`ConditionPathExists=/dev/qcom_rmtfs_mem1`，我们的内核满足 → 装上就会生效，
    所以必须先放 drop-in）；包里另带 `rmtfs-dir.service`（`-s -o /var/lib/rmtfs`），证实了文件模式的用法；文件名 `modem_fs1/modem_fs2/modem_fsc/modem_fsg`。
  - tqftpserv 1.2：把基带请求的 `/readonly/firmware/image/`、`/readonly/firmware/modem_pr`、`/readonly/vendor/firmware_mnt/image/`
    映射到 remoteproc 固件所在目录（读 `/sys/class/remoteproc`），`/readwrite/` → `/var/lib/tqftpserv`。
    所以 `modem_pr/` 放在 `qcom/sm8550/xiaomi/fuxi/` 下即可。

## ModemManager 与通话（10-27 核对 Ubuntu 包）

- Ubuntu 的 ModemManager 1.25.95 依赖 libqrtr-glib、libqmi-glib 1.38 → 支持 QRTR 方式的 SoC 内置基带（无需 USB），
  数据通道走 IPA 的 `rmnet_ipa0` + QMAP（MM 自己建 rmnet 子接口，需要内核 `RMNET`，已开）。
- 短信、移动数据：MM 原生支持。
- 通话：国内运营商大多已关 2G/3G，通话靠 VoLTE。高通基带的 IMS 协议栈在基带内部运行，Android 侧只是配置；
  postmarketOS 上部分高通机型在载入正确的运营商 MBN（`modem_pr/mcfg`，tqftpserv 提供）后 VoLTE 可用。
  所以顺序：先短信/数据 → 用 `qmicli --pdc-*` 查看/选择运营商 MBN → 试 VoLTE 通话（音频还要接 Q6 的语音通路，另做）。

## 基带起来之后（10-27 11:40 准备）
